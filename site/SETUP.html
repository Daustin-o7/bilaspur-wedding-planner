One-time Google setup

Sign in using the wedding owner’s Google account. Allow about 10–15 minutes. Family members will use your private edit link and do not need to do these steps.

Until the website says “Saved to Google”, edits are only on that device. The owner’s Sheet, Drive folder and Calendar are created privately. Nothing needs to be made publicly readable.

1. Create the Apps Script project

  1. Open Google Apps Script, check the account avatar, and choose New project. Name it Bilaspur Wedding Hub.
  2. Open Code.gs, copy all its contents, and replace the editor’s existing Code.gs contents.
  3. In Apps Script, click + → Script, name it Core, and paste all of Core.gs.
  4. Open Project Settings (gear) and enable Show “appsscript.json” manifest file in editor. Return to the editor and replace that file with this manifest. Save the project. The timezone is Asia/Kolkata.

2. Authorize the owner’s storage

  1. Select setupWedding in the function dropdown and click Run.
  2. Review and grant access to Sheets, Drive, Calendar and script triggers for your own project. Google may show an unverified-app screen because this is a personal script you created. Confirm the project and signed-in account before continuing.
  3. Wait for SETUP COMPLETE in the execution log. Running setup again reuses the existing resources.
  4. Under Project Settings → Script Properties, copy FAMILY_KEY privately. It is a 64-character edit key. Do not put it in a GitHub file, issue or screenshot.

3. Deploy the web app

  1. Choose Deploy → New deployment → Web app.
  2. Set Execute as: Me and Who has access: Anyone. Family access is checked by the key inside the script. “Anyone with a Google account” will require sign-in and will not work for this anonymous family-link flow.
  3. Click Deploy and copy the Web app URL ending in /exec. Do not use the /dev testing URL.

4. Connect and share

  1. Return to the planner and open Connection & share. Enter your name, the /exec URL and FAMILY_KEY. Click Connect & load shared plan.
  2. Wait for Saved to Google • revision …. A local backup may download when you change workspaces. Keep it.
  3. Reopen Connection and choose Copy private family edit link. Share that link in the family group. The plain GitHub Pages URL opens a local planner on a new device.
  4. Test on two phones: add a clearly named test task, wait for “Saved to Google”, and check that it appears on the other phone within roughly 10 seconds while no field is being edited. Change it on the second phone, check the first, then delete the test task.

Relatives tap outside a field to commit their change. Changes save locally first, then to Google. Independent edits merge. If two people change the same field, a conflict box lets you download the draft and choose the value to keep. Polling pauses while someone is typing, a dialog is open, or the tab is hidden.

Sheets, Drive, Calendar and Maps

  • Sheet: live records are stored in Hub_State_A/B with a revision in Hub_Control. Human-readable report tabs refresh within five minutes. Edit records through the website; editing report tabs does not update it.
  • Drive: use Budget → Upload a receipt, then copy its URL into the vendor row. Uploads are private PDFs/images up to 5 MB. In Storage, “Save snapshot” makes a complete backup. The scheduled job also backs up changed plans at most once an hour.
  • Calendar: enter exact IST start/end dates for every active event, deactivate unused drafts, then choose “Update shared wedding calendar”. Repeating this updates the same events; inactive/deleted hub events are removed from the dedicated wedding calendar. Personal-copy links create independent events.
  • Access to Google files: the owner can open all resource links. If other relatives need to open a receipt, the Sheet or Calendar directly, share that specific Google resource with their accounts. They can still edit the website without Google sign-in.
  • Maps: the website supplies venue-name searches. Confirm each exact property and entrance with its manager before sharing directions.

Recovery and troubleshooting

  • Invalid response / sign-in page: confirm Execute as Me, access Anyone, the /exec URL, and that setupWedding completed. Managed Google accounts can prohibit public web apps; the owner must use an account that permits this deployment.
  • New backend code: replace Code.gs, Core.gs and the manifest together, then Deploy → Manage deployments → Edit → New version → Deploy. Saving script code alone does not update the deployed web app.
  • Failed network request: keep the tab open and use Download backup. Retry after connection returns. Do not interpret “saved on this device” as a cloud save.
  • Lost edit or accidental delete: Connection → Recover a device draft lets you download another tab’s draft or the last pre-delete copy. Review it, then Restore backup. A restore syncs replacements and deletions to everyone.
  • Corrupted Sheet storage: stop editing, download any readable device drafts, and preserve the existing Sheet. The simplest recovery is a new Apps Script project with the same files, new setup and deployment, then connect and restore the latest Drive/device backup. Share its new family link.
  • Leaked family link: run rotateFamilyKey in Apps Script, copy the new FAMILY_KEY, reconnect the website and share a replacement link. Old keys stop working. This does not revoke copies that were already downloaded.
  • Storage limits: the shared plan is limited to 2 million JSON characters and 100 event cards. Drive and Apps Script quotas also apply. Keep backup downloads and final printed contact/run sheets.

Anyone holding the private family link can read, add, edit and delete the shared plan. Guest contacts, room information and budgets are included. Keep the link within the planning group. On a shared computer, clear this site’s browser data after exporting needed drafts; it remembers the connection and local data.
